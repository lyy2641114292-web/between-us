## 问题与决策

### 01 页「慢」的真实原因（2026-11-16 实测推翻推测）

我最初判断是 `maxTokens: 800` 把两层预生成的响应截断，导致 `chatJSON` 重试三次。实测结果：
- 极简请求（39 token 入 / 5 token 出）就要 **3086 ms** —— 上游基础往返就这么慢
- 真实 probe 两次 11990 / 5245 ms，**服务端无重试日志**，返回仅 482 字符，**没被截断**
- 模型其实从来没生成过两层的 `nextChips`（只给了纯字符串），提示词要求与实际行为长期不一致

结论：慢是上游模型与代理的固有延迟，代码压不下去。改用「阻塞段只出问题+标签，下一问后台预取」，把等待藏进用户阅读时间里。阻塞段从 5~12 秒降到 3.4 秒，点标签降到 0 秒。

教训：先量再改。这次如果直接按推测动手，会改错地方。

### 本次改造的关键决策

1. **轮数由 AI 判断**（用户选择）：AI 返回 `done: true` 即收尾。另加两层保护：
   - 提示词写明「至少 2 轮」「通常 2~5 轮」「第 5 轮必须 done」
   - reducer 硬兜底：`rounds.length >= 4` 时强制 `done = true`
   - 起因：实测出现过跑到 7 轮才收尾的情况
2. **保留自由输入**（用户选择）：A/B 两个草稿可点选，也可自己写她的话，标记区分「表达感受并了解对方 / 解释自己的想法 / 自由输入」。
3. **页面标签去掉「你（自己）」**：用户此刻扮演她，「你（自己）」会和当前身份撞车。统一为「原来的你 / 朋友（她）」。测试里加了断言：页面不得再出现「你（自己）」。
4. **旁白三道防线**：
   - 提示词：明确禁止旁白、动作、心理描写，并给出反面例子
   - `normalizeChat()`：整行被括号/方括号包住的直接丢弃；行内括号旁白剥掉
   - 验证脚本：逐条检查气泡正文无括号内容
5. **降级策略**：一旦某轮降级，`useFallback = true`，后续轮次直接走本地兜底，不再每轮等一次超时。但「还没有记录任何片段」这种临时情况传 `sticky: false`，用户补上记录后仍会尝试真实 AI。

### 踩到的坑

1. **改完提示词后模型仍返回旧的三幕格式**
   根因：8788 端口上是 23:40 启动的旧后端进程，Node 不会热加载 `prompts.mjs`。
   解决：杀掉旧 dev 栈（`scripts/dev.mjs` 的整个进程树）后重新 `node scripts/dev.mjs`。
   教训：改后端文件必须重启后端，不能只看前端 vite 的热更新。

2. **验证脚本一开始全部 FAIL**
   根因：`page.locator('section').first()` 拿到的是已挂载但隐藏的阶段 01，而不是当前可见的阶段 03。
   解决：改成 `Array.from(document.querySelectorAll('section')).find(x => x.offsetParent !== null)`。

3. **`button` 类型里 `border-...` 被 `rounded-full` 覆盖时点不到**
   实际是「完成换位体验」按钮需要在页面底部滚动后才可见。

### 实测对话样例（聚会玩笑故事）

```
左｜那天聚会，你说「这也能叫上线」的时候，我笑了一下，后来就没怎么说话了。
右｜我当时就是随口一说，没想到你会在意。
右｜我那句随口的话让你不舒服了？我当时没觉得有什么，你后来不怎么说话，我还以为你只是累了。
左｜我笑了一下，是因为一桌人都在，我不想当场说什么。但那句话我记住了。
右｜我真不是想让你难堪，我以为那种话你不会往心里去。
右｜我说话确实不太过脑子，但我真没想贬低你，我只是习惯了这样开玩笑。
```

无旁白、无动作、无心理描写，左右人称正确（左=原来的你用「我」称她为「你」；右=她称原来的你为「你」）。
