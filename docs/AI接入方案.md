# AI 接入方案

> 最后更新：2026-11-15
> 状态：**需求确认中，尚未写代码**

## 0. 问题定义

当前应用的数据流是断的：

```
用户写的内容（阶段01）
      ↓
  只显示在右侧时间线
      ↓
      ✗ 断了
      ↓
阶段02「客观事实」「感受与判断」→ 写死的 3+2 条
阶段03 三幕推演           → 写死的「26 小时」「五天静默」剧本
阶段04 气泡与未知项        → 写死的 6+3 条
阶段05 表达草稿           → 写死的三段信
静观对话                → 3 套剧本 + 关键词匹配
```

**用户讲自己的故事，应用讲自己的故事。** 这是必须解决的根本问题。

## 0.1 已确认的决策（2026-11-15）

| 决策项 | 结论 |
|---|---|
| 方案 | **B：云端 API（DeepSeek）** |
| 范围 | **全部五个阶段 + 静观** |
| 密钥 | 用户已有 DeepSeek Key |
| 后端 | 本地 Node 服务（Express，端口 8788） |
| 隐私 | 接受并**告知用户**（首次使用显示说明） |
| AI 内容 | **全部可改**（AI 是初稿，用户是主人） |
| 调用时机 | **进入每个阶段时生成**，结果缓存 |
| 示例数据 | AI 成功后**完全替换**，失败时降级兜底 |

## 0.2 方案对比记录（为什么不选 A / C）

|---|---|---|---|
| 阶段 02 | 显示用户片段 | 真实提取 | 真实提取 |
| 阶段 03–05 | 通用模板 | 真实生成 | 真实生成 |

## 0.3 关键事实（已核实 DeepSeek 官方文档）

- Base URL：`https://api.deepseek.com`
- 端点：`POST /chat/completions`（[OI] 兼容格式）
- 模型：`deepseek-flash`（便宜）、`deepseek-v4-pro`（更强）
- 支持 `response_format: { type: 'json_object' }`（结构化输出）
- 支持 `stream: true`（SSE 流式）
- 价格（deepseek-flash，空闲时段）：输入 ¥1 / 百万 token，输出 ¥4 / 百万 token
- 高峰时段（工作日 9-12、14-18 北京时间）价格翻倍

## 1. 改造目标

让阶段 01 写下的内容，成为后续所有阶段的唯一素材来源。

| 阶段 | 现在 | 改造后 |
|---|---|---|
| 01 记录冲突 | 本地记录 | 不变（仅记录），完成后触发一次分析 |
| 02 理解自己 | 写死 3 条事实 + 2 条判断 | **从用户片段中提取**客观事实、识别判断、给出其他可能性 |
| 03 探索对方 | 写死三幕剧本 | **基于用户情境生成**三幕，每幕的「已确认事件」只引用用户写过的内容 |
| 04 对照视角 | 写死 6 气泡 + 3 未知项 | **基于前四阶段内容生成** |
| 05 决定下一步 | 写死三段草稿 | **基于用户情境生成**三种语气的个性化草稿 |
| 静观 | 关键词匹配剧本 | **真实多轮对话**，带完整上下文 |

## 2. 技术方案

### 2.1 架构

```
浏览器 (React, :5200)
   │  fetch /api/generate   （无密钥）
   ↓
本地 Node 服务 (Express, :8788)
   │  Authorization: Bearer <DEEPSEEK_API_KEY>
   ↓
DeepSeek API (https://api.deepseek.com)
```

**为什么必须有后端**：API Key 放在前端代码里，任何人打开 DevTools 就能看到并盗用。这不是建议，是硬性要求。

**开发时的端口关系**：
- 前端 Vite `:5200`
- 后端 Express `:8788`
- Vite 配置 proxy：`/api` → `http://127.0.0.1:8788`

**上线时**：后端需部署到有 Node 环境的地方（Render / Fly.io / 自己的服务器），前端静态托管。或后端同时托管 `dist/`。

### 2.2 模型与成本

| 项 | 值 |
|---|---|
| Base URL | `https://api.deepseek.com` |
| 端点 | `POST /chat/completions` |
| 推荐模型 | `deepseek-flash`（便宜、够用） |
| 备选模型 | `deepseek-v4-pro`（更强、约 4 倍价格） |
| 结构化输出 | 支持 `response_format: { type: 'json_object' }` |
| 流式 | 支持 SSE |

**单次完整流程成本估算**（deepseek-flash 空闲时段）：

| 环节 | 输入 tokens | 输出 tokens |
|---|---|---|
| 阶段 02 分析 | ~800 | ~800 |
| 阶段 03 三幕 | ~1200 | ~1500 |
| 阶段 04 对照 | ~1500 | ~800 |
| 阶段 05 草稿 | ~1500 | ~1200 |
| 静观（按 10 轮） | ~15000 | ~4000 |
| **合计** | **~20000** | **~8300** |

按 flash 空闲价（输入 1 元/M、输出 4 元/M）：**约 0.05 元 / 次完整使用**。
高峰时段翻倍，约 0.1 元。用 `deepseek-v4-pro` 约 0.25–0.5 元。

### 2.3 接口设计

统一用一个生成端点，按 `task` 分流，减少重复代码：

```
POST /api/generate
body: { task, context, options? }
```

| task | 用途 | 返回 |
|---|---|---|
| `analyze` | 阶段 02：提取事实与判断 | `{ facts[], interpretations[], emotions[], coreNeed }` |
| `explore` | 阶段 03：生成三幕 | `{ acts: [{ confirmedEvent, prompt, options[] }] }` |
| `compare` | 阶段 04：生成气泡与未知项 | `{ selfBubbles[], otherBubbles[], unknowns[] }` |
| `draft` | 阶段 05：生成三种语气草稿 | `{ gentle, brief, nopressure, reflections[] }` |
| `stillpoint` | 静观对话 | 流式文本 + 追问 |

`context` 统一携带：用户片段、已生成的各阶段内容、当前阶段、对话历史。

### 2.4 关键约束（写进 system prompt）

必须原样遵守产品红线（见 `docs/设计规范.md` 7.4）：

1. **绝不生成用户没说过的话** — 阶段 03 的「已确认事件」只能引用用户片段原文或高度忠实的大意
2. **对方视角一律假设措辞** — 「她可能」「也许」「尚待核对」
3. **不判断对错** — 不出现「你没错」「是她不对」
4. **不替用户决定** — 不出现「你应该和好」「你必须沟通」

### 2.5 失败与降级

```
调用 AI
  ├─ 成功 → 使用 AI 结果
  ├─ 超时（15s）→ 降级到现有模板 + 提示「AI 暂时不可用，已使用默认内容」
  ├─ 返回非 JSON → 重试 1 次 → 仍失败则降级
  └─ 网络错误 → 降级 + 提示
```

现有模板代码（`src/data/stage02~05.js`、`src/ai/stillpointEngine.js`）**全部保留**，作为降级兜底。

## 3. 用户已确认的决策（2026-11-15）

### 3.1 隐私告知 → 接受，并告知用户
- 首次使用 AI 功能时，页面顶部显示一次说明，用户确认后继续。
- 文案要点：记录会发送至 AI 服务处理；不保存在我们服务器；可随时关闭 AI 回到纯本地模式。
- 不做「默认关闭」的开关（用户已选「接受并告知」，非保守方案）。

### 3.2 AI 生成内容 → 全部可改
- 阶段 02 的事实、判断、真实需求：保持可编辑（沿用现有编辑交互）
- 阶段 03 的选项：用户可自由输入代替
- 阶段 05 的草稿：保持可编辑 + 三种语气
- 阶段 05 五条反思：保持 contentEditable
- 原则：**AI 是初稿，用户是主人**

### 3.3 调用时机 → 进入每个阶段时生成
- 阶段 02 进入时调用 `analyze`
- 阶段 03 进入时调用 `explore`（携带阶段 02 结果）
- 阶段 04 进入时调用 `compare`（携带阶段 01–03 结果）
- 阶段 05 进入时调用 `draft`（携带阶段 01–04 结果）
- 静观：每次提问时调用 `stillpoint`
- 每阶段生成结果**缓存进 store 并持久化**，同阶段二次进入不重复调用（除非用户点「重新生成」）

### 3.4 旧示例数据 → AI 成功后完全替换
- 现有 `src/data/stage02~05.js` 的示例内容保留为**降级兜底**
- AI 成功 → 用 AI 结果覆盖显示
- AI 失败 → 回落到示例数据 + 明确提示「AI 暂时不可用，已使用示例内容」
- 每个 AI 生成的区块标注来源（AI 生成 / 示例内容），避免混淆

## 4. 实施步骤（共 7 步）

| # | 步骤 | 产出 | 完成标准 |
|---|---|---|---|
| 1 | 后端骨架 + 密钥管理 | `server/index.mjs`、`server/config.mjs`、`.env.example`、`.gitignore`、`启动.bat` 同时拉起前后端 | `npm run dev` 前后端都起；`/api/health` 返回 ok；`.env` 不入库；无 Key 时给明确提示 |
| 2 | DeepSeek 客户端 + 契约 | `server/deepseek.mjs`（调用 + JSON 解析 + 重试）、`server/prompts/` 五个 task 的提示词 | 用一个最小 prompt 跑通真实调用；超时/非 JSON/鉴权失败三条错误路径都有处理 |
| 3 | 阶段 02 接入 | `analyze` task + 前端调用 + 加载态 + 可编辑 | 用户写「同事借钱不还」这类完全不同的故事，事实与判断能正确生成且不含「26 小时」 |
| 4 | 阶段 03 接入 | `explore` task + 三幕渲染 | 三幕「已确认事件」只引用用户写过的内容，不出现编造台词 |
| 5 | 阶段 04 + 05 接入 | `compare` / `draft` task | 气泡、未知项、三种语气草稿均贴合用户情境 |
| 6 | 静观接入（流式） | `stillpoint` task + SSE | 真实多轮对话，能接住用户上一句；上下文包含前面所有阶段 |
| 7 | 降级、错误处理、隐私说明、全链路验收 | — | 断网/超时/无效 Key 均有友好提示并降级；首次使用显示隐私说明；换全新故事五阶段都贴合 |

每步结束停下确认。

## 5. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| AI 编造用户没说过的话 | 违反产品红线 | system prompt 强约束 + 前端标注「AI 推测」 + 用户可改 |
| 输出不是合法 JSON | 页面崩溃 | `response_format: json_object` + 校验 + 重试 + 降级 |
| 用户内容被发送到第三方 | 隐私 | 首次使用告知；提供「仅本地模式」开关 |
| 成本失控 | 账单 | 后端限流（按 IP 每分钟 10 次）+ 单次 max_tokens 上限 |
| 等待时间过长 | 体验差 | 加载态 + 流式输出（静观）+ 超时降级 |
| 密钥泄漏 | 被盗刷 | 只在服务端；`.env` 加入 `.gitignore` |
