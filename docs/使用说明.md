# 使用与部署说明

> 最后更新：2026-11-17

## 〇、第一次运行必做：填写 API 密钥

本项目已接入 AI，需要 DeepSeek 的 API 密钥。

### 1. 申请密钥

打开 https://platform.deepseek.com/api_keys ，创建一个密钥（形如 `sk-xxxxxxxxxxxx`）。

### 2. 填进 `.env`

用记事本打开项目根目录的 **`.env`** 文件，找到这一行：

```
DEEPSEEK_API_KEY=
```

把密钥粘贴到等号后面（**不要加引号**）：

```
DEEPSEEK_API_KEY=sk-你的密钥
```

保存文件。

### 3. 重启服务

双击 `启动.bat`，或运行 `npm run dev`。

启动时会打印密钥状态：

```
  ✓ 已检测到密钥（sk-abc…xyz9），模型：deepseek-flash
```

如果显示 `! 未检测到 DEEPSEEK_API_KEY`，说明没填对或没重启。

> **不填也能启动**：AI 功能会自动降级为内置模板，但内容会比较通用（不是根据你的情境生成的）。

### 密钥安全说明

- `.env` 已在 `.gitignore` 中排除，不会被提交到代码仓库
- 密钥**只在后端**（`server/`）读取，永远不会出现在浏览器代码里
- 页面上的所有 AI 请求都经过本机后端转发

## 一、在本机运行

### 最简方式

双击项目根目录的 **`启动.bat`**。

它会：
1. 检查 Node.js 是否已安装
2. 首次运行时自动安装依赖
3. 检查 `.env` 是否填好密钥
4. 同时启动后端（8788）与前端（5200），并打开浏览器

### 命令行方式

```powershell
cd "e:\claude code\between 3.0"
npm install          # 首次运行
npm run dev          # 同时启动前端与后端
```

访问 **http://127.0.0.1:5200**

### 两个服务分别是什么

| 端口 | 服务 | 作用 |
|---|---|---|
| 5200 | Vite 前端 | 页面 |
| 8788 | Node 后端 | 转发 AI 请求、持有密钥 |

**前端页面上的 `/api/*` 请求会被自动转发到后端**（Vite proxy），所以浏览器里看不到密钥。

### 常用命令

| 命令 | 作用 |
|------|------|
| `npm run dev` | 同时启动前后端（日常用这个） |
| `npm run dev:web` | 只启动前端 |
| `npm run dev:server` | 只启动后端 |
| `npm run build` | 构建生产版本到 `dist/` |
| `npm run preview` | 预览构建结果 |
| `npm start` | 只启动后端；若 `dist/` 存在则同时提供页面 |

## 二、构建与部署

```powershell
npm run build
```

产物在 `dist/` 目录。

**有三种部署方式，按需选一种。**

### 方式 A：单进程（最省事，适合自己一台机器长期跑）

后端会顺带托管 `dist/`，一个地址同时提供页面和 AI，不需要第二个服务。

```powershell
npm run build
$env:HOST='0.0.0.0'        # 让外网能连进来；本机测试可不设
npm start
```

然后访问 `http://服务器IP:8788`。

需要在 `.env` 里设置：

| 键 | 值 | 说明 |
|---|---|---|
| `HOST` | `0.0.0.0` | 不设则只监听本机，外网连不上 |
| `TRUST_PROXY` | `true` | 只有放在 Nginx / Caddy / 云平台后面时才需要 |
| `ALLOWED_ORIGINS` | 可留空 | 同源部署用不到；留空 = 允许任意来源 |
| `RATE_LIMIT` | 默认 `60` | 每个 IP 每分钟允许的模型调用次数 |

这种方式下前端请求的是相对路径 `/api`，**不需要** `VITE_API_BASE`。

### 方式 B：前端静态托管 + 后端单独部署

适合把页面放 Vercel / Netlify / Cloudflare Pages，后端另找一台有 Node 的机器（Render / Fly.io / 自己的服务器）。

1. 先构建前端，构建时告诉它后端在哪：

   ```powershell
   $env:VITE_API_BASE='https://你的后端域名'
   npm run build
   ```

   > `VITE_API_BASE` 是**构建时**变量，改完必须重新 `npm run build`，否则不会进产物。

2. 把 `dist/` 传到静态托管平台（构建命令 `npm run build`，输出目录 `dist`）。
3. 后端那台机器上设置：

   | 键 | 值 |
   |---|---|
   | `HOST` | `0.0.0.0` |
   | `ALLOWED_ORIGINS` | `https://你的前端域名` |
   | `TRUST_PROXY` | 在代理后面时 `true` |

4. `npm start` 启动后端。

**`ALLOWED_ORIGINS` 必须填**：留空等于允许任何网站调用你的后端，别人可以拿你的密钥刷模型。填上后，不在名单里的来源会收到 403。

### 方式 C：Cloudflare Pages + Pages Functions（当前线上方案）

页面与 AI 后端都在同一个 Pages 站点上，**同域名、不跨域、不需要另开服务器、不用你自己的电脑开机**。

**结构**：

```
functions/api/[[path]].js   →  处理 /api/*（Workers 运行时）
src/                        →  前端
public/_routes.json         →  只把 /api/* 路由给函数，静态资源直接发
```

**与方式 A/B 的关键区别**：前端**不需要** `VITE_API_BASE`，请求走相对路径 `/api`，同源。

**首次部署**：

1. Cloudflare 后台 → **Workers & Pages** → 选你的 Pages 项目 → **Settings**
2. **Environment variables** → 添加（Production 与 Preview 都加）：

   | 变量 | 值 | 必填 |
   |---|---|---|
   | `DEEPSEEK_API_KEY` | 你的密钥 | **是** |
   | `DEEPSEEK_BASE_URL` | 代理地址（用官方就留空） | 否 |
   | `DEEPSEEK_MODEL` | `deepseek-flash` | 否 |
   | `ALLOWED_ORIGINS` | 留空即可（同源部署用不到） | 否 |
   | `RATE_LIMIT` | `30` | 否 |

3. **Settings → Build** 确认：构建命令 `npm run build`，输出目录 `dist`
4. **Deployments → Retry deployment**（或重新推送代码），让函数生效

**限流说明**：Pages Functions 没有跨请求共享的内存，限流改为按 Cloudflare 的 `CF-Connecting-IP` 计数，但**每个边缘节点各自计数**，不同地区访问时额度不共享。这是 Workers 架构的固有限制，不是 bug。真正的全局限流需要 KV 或 Durable Objects，属后续可选项。

**如果只想本地跑 Workers 预览**：

```powershell
npx wrangler pages dev dist --compatibility-date=2024-11-01
```

（密钥从 `.env` 读不到，需要用 `--binding` 或 `.dev.vars` 提供。）

### 部署前的三点注意

1. **必须走 HTTP/HTTPS，不能用 `file://` 直接打开**——语音识别等浏览器 API 需要安全上下文。
2. **`dist` 体积约 38.8MB**，其中 37.7MB 是字体、共 1272 个字体文件。这是正常的（见第五节）。
3. 若托管平台有单文件数量限制（如某些免费套餐限 1000 个文件），当前 1275 个文件可能超限。解决办法见第五节。

## 三、数据存在哪里

- 你填写的内容存在**当前设备的浏览器里**（`localStorage`）。
- 使用 AI 功能时，内容会**发送到 DeepSeek 服务器**处理（详见第二节隐私说明）。
- 本项目自己的服务器**不保存**任何用户内容，只做转发。
- 换电脑、换浏览器、清除浏览器数据 → 内容会丢失。
- 页面左下角有「清空本机数据」按钮（需二次确认）。
- 「导出反思档案」会把五条反思存成 `.txt` 文件到你的下载目录。

## 四、隐私说明

**开启 AI 功能后，你的记录会被发送到第三方 AI 服务。**

| 项 | 说明 |
|---|---|
| 发送什么 | 你在五个阶段填写的文字内容 |
| 发送给谁 | DeepSeek（https://api.deepseek.com） |
| 为什么 | 只有这样才能生成贴合你情境的分析，而不是套用通用模板 |
| 本项目服务器是否保存 | **否**，只做请求转发 |
| 能否不用 AI | 可以。不填密钥时自动使用内置模板（内容较通用） |

> 如果这段内容对你来说是敏感的个人信息，请在使用前考虑清楚。

## 五、字体体积说明

字体文件占 `dist` 的绝大部分：

| 字体族 | 体积 | 文件数 |
|---|---|---|
| Noto Serif SC | 20.5 MB | 588 |
| Noto Sans SC | 15.7 MB | 588 |
| Inter | 0.8 MB | 56 |
| Cormorant Garamond | 0.7 MB | 40 |
| **合计** | **37.7 MB** | **1272** |

**为什么这么大**：中文字体按 Unicode 区间拆成 101 个子集 × 3 个字重 × 2 种格式。

**为什么实际不影响使用**：浏览器只下载**页面实际用到的字**所在的子集。首屏通常只加载几个子集（约几百 KB），不是 37.7MB。

**如果托管平台限制文件数**，可以改为单文件子集（每字重约 1.4MB，总约 12MB / 18 个文件）：

```js
// src/styles/fonts.css 中，把
@import '@fontsource/noto-serif-sc/300.css';
// 改为
@import '@fontsource/noto-serif-sc/chinese-simplified-300.css';
```

代价：用户会一次性下载整个中文字集（约 1.4MB/字重），而不是按需下载。

## 六、语音识别

- 使用浏览器内置的 Web Speech API，**不需要任何密钥、不产生费用**。
- 仅 **Chrome / Edge** 支持。其他浏览器点击后会提示「当前浏览器不支持语音识别」。
- 首次使用需要授予麦克风权限。
- 识别准确度一般，可能需要手动修正文字。
- 语音在本机识别，不上传本项目服务器。

## 七、AI 功能现状

五个阶段与静观**都已经接入真实模型**（DeepSeek），不是本地剧本。

| 环节 | 说明 |
|---|---|
| 调用方式 | 浏览器 → 本机后端 `/api/*` → DeepSeek，密钥只在后端 |
| 失败时 | 自动降级为内置模板，界面上会明确提示，并提供「重试」 |
| 不填密钥 | 全流程仍可走完，只是内容比较通用 |
| 静观 | 流式返回，边生成边显示 |

`src/ai/provider.js` 里的 `USE_REAL_LLM` 是早期预留开关，当前未参与实际调用，可以忽略。

提示词全部在 `server/prompts.mjs`，产品红线（见 `docs/设计规范.md` 7.4）已写进提示词：
不生成用户没说过的话、对方视角用假设措辞、不判断对错、不替用户决定是否修复关系。

## 八、遇到问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 打不开页面 | 端口被占用 | 关掉占用 5200 的程序，或改 `vite.config.js` 的 `port` |
| 双击 `启动.bat` 闪退 | 未安装 Node.js | 安装 https://nodejs.org/zh-cn |
| 内容刷新后没了 | 浏览器隐私模式 / 清除了数据 | 正常模式下使用；隐私模式不保证保存 |
| 语音按钮没反应 | 非 Chrome/Edge，或拒绝了麦克风 | 用 Chrome/Edge，并允许麦克风权限 |
| 字体看起来不对 | 字体文件未加载 | 检查控制台；确认 `dist/assets` 里有 `.woff2` 文件 |
| 页面某块显示「暂时无法显示」 | 该组件运行出错 | 点「重试」或刷新；错误信息会显示在框里 |
| 提示「AI 调用次数已达上限，约 1 分钟后可继续」 | 每分钟调用次数超过 `RATE_LIMIT`（默认 60） | 等一分钟；若多人共用后端，调大 `RATE_LIMIT`，并确保 `TRUST_PROXY` 配好以便按访客 IP 分别计数 |
