## G5 阶段 05 草稿侧重（2026-11-16 用户验收后指定）

**用户问题**：05 页「你现在希望如何面对这段关系？」切换两个方向后，回复草稿完全一模一样。

**根因（三处叠加）**：
1. `S5_TONES` 兜底文案只有一套，与意愿无关
2. `useStage05AI` 的 `intentChanged` 要求 `aiStatus === 'ai'`，一旦降级为 `template` 就永远不会重新生成
3. `s5/selectIntent` 切换时完全不改 `draft`，用户看到的是旧文字

**改法**：
- `src/data/stage05.js`：`S5_TONES` → `S5_TONES_BY_INTENT`（express / explain 各三语气）+ `S5_TONE_LABELS` + `s5TemplateDraft()`；**改写原型既有文案，用户已授权**（记入 `docs/复刻差异清单.md` 3.8）
- `src/state/store.js`：`s5/selectIntent` 切换时立即换成本意愿的草稿；`s5/switchTone` 仅在「AI 草稿属于当前意愿」时用 AI 版；`s5/aiFail` 同时写 `aiIntentSignature` 与 `aiSourceSignature`（否则 `aiStatus` 永远停在 loading）
- `src/stages/stage05/useStage05AI.js`：`intentChanged` 放宽到 `template` 状态，降级后切换意愿也会重试
- `src/stages/Stage05Decide.jsx`：语气按钮改用 `S5_TONE_LABELS`
- `server/prompts.mjs`：express / explain 由「互斥」改为**主次表**（主体 / 陪衬 / 必含 / 结尾），允许重叠；反思加 ≤30 字硬约束与正反例

**浏览器实测**：
- 切到「解释自己的想法」→ **739ms 内**草稿立即变化，两份内容明显不同 ✅
- AI 返回后 `aiStatus: 'ai'`，草稿替换为 AI 版本 ✅
- 五条反思：10 / 14 / 16 / 13 / 16 字，全部 ≤30 ✅

## G5b 草稿按方向分开缓存（2026-11-16 用户反馈后追加）

**用户反馈**：切换方向再切回来，草稿会变；草稿不需要一直刷新，只要有一版就够。

**根因**：只有一组 `aiDrafts` + `aiIntentSignature`，切到另一方向时签名对不上 → 触发重新生成 → 覆盖原方向那组草稿。

**改法（用户选定：按方向保留手改、重新生成只影响当前方向）**：
- `store.js` stage05：`aiDrafts` / `aiIntentSignature` →
  `aiDraftsByIntent`（各方向 AI 原始版）、`draftsByIntent`（各方向当前正在用的文字，含手改）、`aiTriedIntent`（各方向是否已请求过）
- 新增 `draftFor()`：优先当前文字 → 其次该方向 AI 版 → 最后兜底文案
- `s5/selectIntent` / `s5/switchTone` 都走 `draftFor`，**切换不再请求 AI**
- `s5/setDraft` 手改同时写进 `draftsByIntent[当前方向][当前语气]`
- 新增 `s5/clearCurrentIntentCache`：「重新生成」只清当前方向，另一方向原样保留
- `useStage05AI.js`：已有该方向缓存 → 直接返回；已试过且内容没变 → 不再自动重试
- `persist.js`：`VERSION` 5 → 6，`MIGRATABLE_FROM = [4, 5]`，新增 `migrateStage05Drafts` 把旧档那组草稿归到它当时的方向

**浏览器实测**：
- express / explain 各生成一次后，**来回切换 3 次，两边内容完全不变** ✅
- `cached: ["express","explain"]`，两个方向各自独立 ✅
- `pageerror` 0、`console.error` 0 ✅

## AI 接入完成后的数据流

```
阶段01 用户写的片段
   ↓ analyze
阶段02 客观事实 / 感受与判断 / 情绪 / 真实需求  ← AI 生成，可编辑
   ↓ explore（携带阶段02结果）
阶段03 角色互换纯对话（左=原来的你 / 右=朋友（她））  ← AI 生成，只有对话，无旁白
   ↓ compare（携带阶段01-03）
阶段04 双视角气泡 / 三个未知项                 ← AI 生成
   ↓ draft（携带阶段01-04）
阶段05 三种语气草稿 / 五条反思                 ← AI 生成，可编辑
   ↓ stillpoint（流式，带全部上下文）
静观 真实多轮对话
```

任一环节失败 → 自动降级到内置模板 + 明确提示 + 可重试。

## 限流与后台预取的冲突（2026-11-17）

| # | 步骤 | 产出 | 完成标准 | 状态 |
|---|------|------|----------|------|
| R1 | 量化 | 实测限流边界 + 一次完整会话的请求数 | 知道会在第几次被拒、整场需要多少次 | ✅ |
| R2 | 限流只统计真实模型调用 | `server/index.mjs`（先校验 task 再计数）、`server/config.mjs`（`RATE_LIMIT`） | 无效请求不占额度；被拒请求不累计；阈值可配置 | ✅ |
| R3 | 429 的可读提示 | `src/ai/client.js`（`post` / `stillpointStream`） | 前端显示「约 1 分钟后可继续」而不是「AI 服务返回异常」 | ✅ |

**R1 实测**（临时端口，避开模型调用）：

| 检查项 | 结果 |
|---|---|
| 固定阈值 20 时的边界 | 第 1~20 次放行，**第 21 次起 429** |
| 无效任务（`task` 拼错）是否占额度 | 改前**占**，10 次无效请求把正常额度吃掉一半 |
| 被拒请求（429）是否累计 | 改前**累计**，用户越重试锁得越久 |

**一次完整五阶段会话的请求估算**：

| 阶段 | 请求 |
|---|---|
| 01 记录冲突（每轮 1 次 probe + 1 次后台预取，常答 2~3 轮） | 4~6 |
| 02 理解自己 | 1 |
| 03 探索对方（每轮 1 次 explore + 1 次预取，2~4 轮） | 4~8 |
| 04 对照视角 | 1 |
| 05 决定下一步（每方向 1 次 draft，切换两方向） | 1~2 |
| 静观（每打开一次开场 + 每轮对话） | 1~3 |
| **合计** | **约 12~21，走完全程通常 20~30** |

结论：固定 20 次/分钟对「快速连续作答」的用户明显偏紧。

**R2 改法**：
- `handleGenerate` 改为「读 body → 校验 task → 通过后才计数」，无效任务 400 且不占额度
- 拆成 `isRateLimited()` / `recordHit()`；被 429 拒绝的请求**不再写入计数**，锁定时长固定为最后一个有效请求之后 60 秒
- 阈值从硬编码 20 改为 `RATE_LIMIT` 环境变量，默认 **60**
- 顺带清理长期不活跃的 IP 记录，避免 `hits` Map 无限增长

**R2 实测**（`RATE_LIMIT=3` 加速验证）：

| 场景 | 结果 |
|---|---|
| 10 次无效任务后连续有效请求 | 前 3 次 200，第 4 次 429 —— 无效请求确实不占额度 ✅ |
| 打满后连续被拒 5 次，再等 62 秒 | 恢复 200 —— 被拒请求不再累计、不会无限延长锁定 ✅ |
