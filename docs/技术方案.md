# 技术方案

> 最后更新：2026-11-15

## 1. 技术栈

| 类别 | 选型 | 版本 | 理由 |
|------|------|------|------|
| 构建 | Vite | 5.x | 用户指定；启动快、配置少 |
| 框架 | React | 18.x | 用户指定；组件化拆解 5 个阶段视图 |
| 语言 | JavaScript (JSX) | — | 原型为纯 JS，无类型迁移成本 |
| 样式 | 原生 CSS（`src/styles/`） + Tailwind | 3.4.x | **见下方 D1**：原型的 498 处 class 全部是 Tailwind 工具类，其中 447 处是任意值写法，只能由 Tailwind 编译 |
| 图标 | 内联 SVG | — | 原型已全部内联，不引第三方图标库 |
| 字体 | 自托管 Cormorant Garamond / Inter / Noto Serif SC / Noto Sans SC | 与原型一致 | 断网可用、不受网络影响；见 `docs/复刻差异清单.md` 3.1 |
| 语音识别 | 浏览器 Web Speech API（`SpeechRecognition`） | 浏览器内置 | 不引第三方服务、无费用；Chrome/Edge 可用，不支持时降级提示 |
| 图形 | 原生 Canvas 2D + WebGL（手写 GLSL） | — | 原型已手写 shader，无第三方 3D 库 |
| 持久化 | `localStorage` | — | 数据量小（纯文本），不需要 IndexedDB |
| AI 接口 | 自定义 provider 模块 | — | 本阶段只留接口，不实现网络调用 |

### D1 已确认：方案 A（装 Tailwind 构建）【2026-11-15 用户确认】

原型用 `<script src="https://cdn.tailwindcss.com">` 在浏览器里实时编译 Tailwind。
真正可运行的应用**不能**用 CDN 版（上线慢、控制台警告、class 全靠网络）。

两条路：

- **方案 A（推荐）**：安装 Tailwind 到项目里，用构建时编译。
  - 做法：`tailwind.config.js` 里复刻原型 `tailwind.config` 的自定义色板与字体；把原型 `<style>` 整块搬成 `src/styles/`。
  - 收益：498 处 class 原样保留，**视觉零漂移**，改动量最小。
  - 代价：多一个构建依赖（不算"原生 CSS"，但产物仍是纯 CSS）。
- **方案 B**：彻底改为手写 CSS，逐个替换 498 处 class。
  - 收益：完全"原生 CSS"。
  - 代价：约 1500+ 行 CSS 重写，漂移风险极高，工期至少多一倍。

> 用户已确认按方案 A 推进：Tailwind 3.4.x 构建时编译，产物为普通 CSS 文件，不依赖任何 CDN。
> 方案 B（全量手写 CSS）不采用，除非后续出现 Tailwind 无法表达的原型效果。

模块职责一句话：
- `atmosphere/` 只画背景，不碰业务。
- `stages/` 一个文件对应原型一个 `<section>`，负责该阶段的渲染与交互。
- `state/` 是唯一数据源，跨阶段联动通过它完成，不在组件之间互相传。
- `ai/` 是唯一允许写"AI 会说什么"的地方，未来换成真实模型只改这里。

## 3. 关键流程

**A. 应用启动**
1. 读 `localStorage` 里的存档 → 无则用 `initialData`
2. 挂载氛围层（两处 canvas 只挂一次，全程常驻）
3. 默认显示首页视界

**B. 阶段切换**
原型是用 `display:none` + 类名开关切换 `.stage-view`。改造后改为 React 条件渲染：
1. 目标阶段卸载/挂载
2. 保留原型的 240ms 先淡出后淡入时序（由 CSS 过渡负责）
3. 同步右上徽章、底部导航高亮、静观上下文

**C. 02 ⇄ 03 双星位置互换**
原型用遮罩 + 三次 `setTimeout`（480ms / 920ms）。
改为 `useEffect` 驱动的过渡状态机，卸载时清理定时器，避免快速连点导致时序错乱。

**D. 跨阶段数据联动**
- 阶段 02「真实需求」→ 阶段 04 抽屉、阶段 05 第 1 条反思
- 阶段 05「下一步意愿」→ 第 5 条反思文案、显示草稿面板或留白面板
两者都通过 store，删掉原型里 `syncCrossStageData()` 这种命令式同步。

**E. 静观回复**
1. 用户输入 → `stillpointEngine.reply()` 按当前上下文关键词匹配
2. 命中分支 → 返回回复段落 + 下一组提问
3. 未命中 → 返回兜底回复
4. 未来接入真实模型：`provider.js` 里替换第 1 步，其余不变

## 4. 数据模型

```js
// store 的唯一形态（key 与原型变量一一对应，便于比对）
{
  stage01: {
    step: 1,                    // 1..4
    fragments: [],              // 用户写下的片段（原型只存在 DOM 里，改造后必须进 state）
    coreSummary: '',
    quotes: ''
  },
  stage02: {
    emotions: [...],            // [{id,label,color,rgb,selected}]
    coreNeed: '...',
    needCondensed: false,
    facts: [...],               // [{id,text}]
    interpretations: [...]      // [{id,statement,filterTag,aiPrompt,expanded,shelved,alternatives,quickSuggestions}]
  },
  // 角色互换模式（2026-11-16）：rounds 累计 { chat[], question, options[], reply, replyKey }，
  // options 为四个情绪角度 [{ key, text }]；选中或自由输入后追加一轮；AI 返回 done 即收尾
  stage03: {
    rounds: [],                 // 已完成轮次
    current: null,              // 当前待回应的一轮（含 insightHint/insights 当 done 为 true）
    done: false,
    insights: [], note: '',
    aiStatus, aiError, aiSourceSignature, useFallback
  },
  stage04: { selfId, otherId, unknownId, activeContextKey, drawerOpen },
  stage05: { intent, tone, draft, reflections: [...] },
  stillpoint: { open, messages: [], questions: [], focusKey },
  ui: { view: 'home'|'stage', stageIndex, toast }
}
```

存档格式：`{ version: 1, savedAt, data }`。版本号用于未来结构变化时丢弃旧档，避免报错。
清空入口放在页脚一行小字，二次确认后 `localStorage.removeItem`。

## 6. 风险与备选

| 风险 | 影响 | 应对 |
|------|------|------|
| Tailwind 任意值 class 编译后与原 CDN 版有细微差异 | 视觉漂移 | 每阶段完成即逐屏对比截图；差异大于 1px 视为未完成 |
| WebGL shader 在部分显卡/浏览器降级 | 首页背景变纯色 | 复用原型的 `if (!gl) return` 降级路径，另加 2D 后备 |
| Google Fonts 国内加载慢或被墙 | 字体回退到系统字体，观感明显变化 | **已决策自托管**：14 个字重装入项目，`@font-face` 自声明 |
| CJK 字体体积大（Noto Serif/Sans SC 各 3 字重） | 首屏首次加载变慢、项目体积增加 10–20MB | 只装用到的 3 个字重；本地文件走缓存；构建后检查产物体积 |
| 原型把数据存在 DOM 里（片段、气泡都是动态生成的节点） | 刷新即丢，无法联动 | 改造时必须全部收进 store，这是工作量主要来源 |
| 原型 58 处 `onclick` 内联调用全局函数 | 与 React 冲突 | 逐个改为组件内事件处理器，不留 `window.xxx` 全局函数 |
| 动画定时器未清理 | 快速切页时错位、内存泄漏 | 统一用 `useEffect` 返回值清理；提交前检查所有 `setTimeout` |
| 一次重写全部 5 个阶段 | 中途长期打不开、难定位问题 | 严格按步骤推进，每步结束都能 `npm run dev` 打开 |

## 7. 验收方式

- 每步结束：`npm run dev` 打开，按该步「完成标准」逐条走一遍。
- 全阶段完成后：对照 `6.html` 与改造版并排截图，逐屏比对。
- 构建验证：`npm run build` + `npm run preview` 再走一遍完整剧本（共约 15 步）。
