# 设计规范

> 最后更新：2026-11-15

## 1. 代码规范

- **目录结构**：见 `docs/技术方案.md` 第 2 节，不新增顶层目录。
- **命名**：
  - 组件文件 `PascalCase.jsx`（`Stage02Understand.jsx`）
  - 普通模块 `camelCase.js`（`stillpointEngine.js`）
  - CSS 类沿用原型命名（`glass-panel`、`paper-surface`、`scatter-dot`），不改名以免与视觉规范脱节
  - 状态字段沿用原型变量名去前缀（`s2CoreNeedText` → `stage02.coreNeed`），便于逐行对照原型
- **注释语言**：中文。保留原型中解释视觉/交互意图的注释，删除纯装饰性的分节号。
- **格式化**：每文件不超过约 250 行；超过即拆分组件或抽 hook。
- **组件边界**：
  - 只在 ≥2 个阶段使用的组件才放进 `src/shell/` 或 `src/atmosphere/`
  - 阶段私有子组件就近放在同文件，不提前抽象
- **禁止**：
  - 在组件里写 `window.xxx = function` 的全局函数
  - 用 `document.getElementById` / `querySelector` 操作自己渲染的 DOM
  - 在 JSX 里内联 `onclick="..."` 字符串

## 2. 状态与持久化

- 唯一数据源是 `src/state/store.jsx`，组件只读 state、只发 action。
- 原型里"数据藏在 DOM 节点里"的部分（片段列表、对话气泡、反思五条）**必须**进 state。
- `localStorage` 写入策略：状态变化后防抖 400ms 写入，避免每敲一个字就写盘。
- 读取失败（JSON 损坏 / 版本不符）→ 用 `initialData` 并提示「上次的存档无法读取，已重新开始」，不白屏。

## 3. 错误处理

- 无后端，错误面主要是：存档损坏、canvas 不可用、剪贴板不可用。
- 一律给中文人话提示（走 Toast），不抛裸异常、不显示英文报错。
- `copyS5Draft`：`document.execCommand('copy')` 失败时回退到 `navigator.clipboard.writeText`，两者都失败则提示「请手动全选复制」。

## 4. 日志

- 开发期允许 `console.warn` 记录非致命降级（如 WebGL 不可用）。
- 不写 `console.log` 调试语句进最终代码。
- 不记录用户填写的任何内容到日志。

## 5. Git 提交

- 格式：`type(scope): 描述`，如 `feat(stage02): 情绪胶囊联动恒星光环`
- 每完成一个步骤提交一次，提交前确认该步可运行。
- 提交与推送需用户确认，不擅自执行。

## 6. 测试规范

- 允许范围：单文件 / 单用例。
- 超时：60s。
- 禁止：watch、压测、无限循环、无超时命令、全量 E2E 反复运行。
- 本项目第一阶段不引入自动化测试框架；验收以「打开页面逐条走完成标准」为准。

## 7. UI 规范

### 7.1 视觉基线

以原型 `6.html` 为唯一视觉真相。任何改造都不得改变：

- 色板：`abyss #050911`、`deepsea #0A1324`、`mistblue #4A6B82`、`slatefrost #8BA6BC`、`mistwhite #E6ECF2`、暖橙 `#f28c38`、天青 `#5da9e9`、mistviole `#525174`
- 字体：标题 `Cormorant Garamond` + `Noto Serif SC`；正文 `Inter` + `Noto Sans SC`
- 缓动：主过渡 `cubic-bezier(0.22, 1, 0.36, 1)`，不得换用其他曲线
- 关键尺寸：圆镜 154px、光晕 450px、玻璃面板圆角 16–26px

### 7.2 材质类（必须复用，不重复写）

`glass-panel` / `paper-surface` / `paper-grain-overlay` / `s2-abyss-glass` / `glass-other` / `glass-warm-solid` / `hero-focal-card` / `wing-card` / `reflection-scroll-sheet` / `cta-warm` / `emotion-pill` / `reaction-pill` / `insight-chip` / `intent-card` / `expand-drawer`

### 7.3 双色语义

- 暖橙 `#f28c38` = 我 / 自我 / 主动
- 天青 `#5da9e9` = 对方 / 换位 / 倾听
两色不得混用；新增元素先判断属于哪一侧。

### 7.4 文案红线

- 对方视角一律使用假设措辞（「也许」「可能」「尚待核对」），不得写成已确认事实。
- 不出现「你应该」「你必须」「你们应该和好」这类判断句。
- 保留原型中所有「已确认事件」「保留为未知」「不必认同对方」等中立标签。
- 任何「AI 会说什么」的文本只能写在 `src/ai/` 下。
- 阶段 03 角色互换模式（2026-11-16 用户指定）：
  - 只有纯对话，**禁止任何旁白、动作、心理描写**（不得出现「（沉默了一会儿）」「她握紧手机」这类内容）
  - 左气泡固定为「原来的你」，右气泡固定为「朋友（她）」，不得互换
  - 提问语必须带明确主语，如「站在朋友的位置，你会怎么回应？」
  - 回应区固定为**四个情绪角度**草稿：每条 2~4 字关键词标题 + 1~2 行台词；四个角度必须互相能区分，不得只是换措辞
  - 换位觉察卡的引导语与觉察项**由 AI 按本次对话生成**，人称只用「你」与「朋友」，不出现「她」
  - 页面不出现独立的「角色互换」说明栏，角色信息由轨道头图承载
- 阶段 05 文案（2026-11-16 用户指定）：
  - `express` 与 `explain` 两份草稿**各有侧重、允许重叠**：前者以我的感受为主体、末尾了解朋友；后者以当时的想法与动机为主体、末尾不施压；主次必须不同，不能只换几个词
  - 五条反思每条 **≤30 字**，只留一个核心判断

### 7.5 无障碍与降级

- 所有按钮保留 `type="button"`，保留原型已有的 `aria-label`。
- **不做** `prefers-reduced-motion` 适配（2026-11-15 用户决策：与原型行为保持一致）。
- 背景 canvas 不可用时不得白屏，底色 `--bg-abyss` 兜底。
- 语音识别不可用时给中文提示，不抛异常。

### 7.6 禁止替代

原型使用的技术必须原样保留，不得换成"同款"第三方方案。完整清单见 `docs/复刻差异清单.md` 第 4 节，要点：
- WebGL shader、Canvas 2D、内联 SVG、CSS `@keyframes` / `transition` 一律手写保留
- 不引入图标库、动画库、组件库、状态持久化库
- Tailwind 只改编译时机（CDN → 构建），class 与配置不变
